# 懒猫远程

独立 LPK 的显示名称为“懒猫远程”，包 ID 保持 `cloud.lazycat.lightos.remote-desktop`，可直接覆盖升级。管理页使用新的黑白灰矢量图标和设备卡片，支持明暗主题。沿用管理页面的 `lzcapp-navigation-bar-scheme=hidden`、自主管理暗色主题和 `--lzc-safe-area-*` 约定，尊重宿主状态栏与关闭按钮的占位。

## 物理机控制

PC 客户端主进程内的控制模块常驻运行，不依赖远程桌面二进制是否安装。模块负责登记设备、报告状态、安装更新以及启停，图形管理入口都在 LPK 页面。首次使用不安装、不启动采集；卡片显示“未安装”和“安装远程桌面”。

LPK 内含四个平台的原生程序、同版本硬件编码辅助程序和必要的 FFmpeg 动态库：macOS Apple Silicon、macOS Intel、Windows x64、Linux x64。每张物理机卡片显示已安装版本；与 LPK 中版本或程序摘要不一致时提供“更新远程桌面”。安装和更新都由用户点击，显示下载字节、百分比、关闭服务、校验、安装、清理及失败原因。

客户端通过当前登录微服的应用域名（如 `https://remote-desktop.boxname.heiyu.space`）取得清单，只下载匹配自身系统和架构的包。下载经过原有微服认证及 HTTPS 校验，不跳转到第三方下载站。安装前校验压缩包和程序 SHA-256、实际程序版本；macOS 还验证应用签名及后续更新的签名团队。已开启时先提示更新会中断连接；取消保持现状，确认后自动停止服务再下载安装，并在成功后恢复开启状态。已关闭时直接更新且保持关闭。新版本检查通过后提交当前版本并删除旧程序，立即隐藏进度；失败保留原版本、恢复原有可用状态并提供重试入口。程序、安装状态及启停意图存于客户端用户数据目录的 `remote-desktop/managed`，运行时配置存于版本目录之外。

原生 `lightos-remoted` 保持独立运行能力，主要入口为：

- `agent`：兼容独立部署的控制程序；PC 客户端内置控制模块负责 LPK 安装更新。
- `serve`：实际屏幕采集与控制服务，仅由控制程序按用户选择启动。
- `permissions` / `permissions --request`：真实系统能力诊断与本机授权申请。读取状态不会请求授权。

独立运行 `lightos-remoted agent` 即可复用现有 PC 客户端已登录的懒猫网络；不需要重新登录或运行第二个网络核心。程序从当前用户的 `~/.config/lzc-client-desktop/core.cfg` 读取公开本机接口配置，也可用 `--client-config` 显式指定；用 `--state-dir` 指定私有状态目录。Windows 在没有 Electron Cookie 时使用公开的 Shell API 取得当前登录令牌。登录凭据不进入日志、设备列表或持久化管理元数据。

控制程序通过 `LocalServiceGateway` 注册受随机凭据保护的控制服务和桌面服务，使用现有设备通道，不依赖终端、PTY、LightOS 应用或新增网络核心接口。使用默认微服及其当前账号，控制、连接与权限查看遵守原有账号和设备归属校验。切换账号或网络不可续验后停止本机桌面并撤销旧控制授权。

PC 安装包不再内含远程桌面程序，设置中不提供远程桌面开关和权限入口。PC 启动控制模块，以私有状态目录的进程锁避免重复运行。关闭桌面仅停止采集服务，控制模块及设备卡片保持可用；用户明确的启停状态绑定当前账号和设备。客户端退出时回收子进程，异常退出时原生服务通过父进程管道关闭。

macOS 必须在已登录 GUI 会话中运行控制程序，使用稳定应用包以关联屏幕录制和辅助功能授权；独立部署可使用 GUI LaunchAgent。Windows 必须在交互用户会话中运行，不能把 SSH 的非交互会话当作桌面；独立部署使用交互用户任务。权限只能由系统和设备本机用户授予，拒绝后不会定时弹窗。

## 设备登记与预览

物理机直接向本应用 `POST /api/hosts` 登记和续期，包括关闭及等待权限的设备。列表分为“在线设备”和“离线设备”；离线后卡片保留在下方分类，上线后自动移回在线分类并保留封面。旧的已就绪桌面登记仍兼容。新登记的控制服务信息与桌面认证密码仅供服务端使用，公开列表不包含这些凭据。每次控制与连接都重新验证设备归属和在线状态，35 秒未续期不再接受新的控制和连接。

首次出现且没有连接画面的设备显示“暂无预览”。成功连接托管物理机后，浏览器仅从用户实际看到的有效画面生成缩略图，经同源认证保存；关闭、断开、离线或管理服务重启均保留上次有效画面。设备身份与预览位于 `/lzcapp/var/remote-desktop`，按账号隔离，凭据不落盘。LightOS 实例沿用来源已提供的连接 URL，经当前账号用户委托在本应用内转发；页面仅在连接过程中采集已实际绘制的桌面帧，无需升级既有实例桌面程序。连接和预览更新持续验证来源授权，不把图标或假画面冒充截图。

列表通过微服网关提供的当前会话稳定设备 ID 识别本机，保留卡片但禁用连接按钮，文案为“当前设备”；安装、更新、权限与启停按实际状态可用。设备身份随登记元数据保存，服务重启后仍可识别本机；身份未知时不按名称、IP 或系统猜测。直接访问旧的本机桌面链接也会被阻止，需从另一台设备连接该电脑。

管理页没有刷新按钮，可见时自动刷新并保留现有卡片、焦点和操作状态；返回页面后立即更新。物理机和实例的权限行与底部连接操作保持对齐，申请权限仅在有未授权权限时显示在状态右侧；部分来源失败时保留其他设备。容器来源继续消费既有 `/api/list` 和 `remote_desktop_url`，不要求升级 LightOS；调用沿用平台用户委托，不制造票据或固定管理员身份。

## 构建与验证

从 0.1.43 起，Linux Portal 的独立权限申请由运行时 `permissions --request` 处理：在当前物理会话请求系统批准、验证首帧、保存可恢复授权并结束临时会话，随后重新检测保存结果。管理页保留“申请系统权限”按钮并展示进度，不打开桌面页，也不改变启停意图。“刷新状态”只读取诊断结果；自动检测不会发起授权。已批准状态下普通连接不显示首次授权等待提示。该流程属于已登录会话授权，不能当作锁屏及登录前物理屏幕的系统级无人值守支持。

Portal 检测只对真实提供者描述文件和注册目录检查加载时间；不存在的搜索目录记录其缺失状态，祖先目录仅检查路径身份及符号链接是否发生变化。普通应用修改 `~/.local/share` 等通用目录不会触发会话不匹配。组件启动或所有者切换造成的暂态探测失败会在原有总超时内自动重试一次；过程仅做只读能力检查，并通过 D-Bus 正常激活已安装服务，不重复发起用户授权。健康接口提供控制连接占用与输入释放失败状态，供区分连接占用和采集故障。

KDE 的 KWin 可能带有 `CAP_SYS_NICE`，普通用户无法读取它的进程描述符。在该访问确实被系统拒绝时，运行时验证 `org.kde.KWinWrapper` 的进程身份、系统拥有的启动器、KWin 的直接父子关系、明确传入的 Wayland FD 与显示名称，再核对启动器持有的真实监听 socket。系统权限保持原样，不要求 root 或放宽进程保护；未知启动器、跨用户、不同显示及无法验证的关系仍拒绝连接。

Linux 物理机按运行时报告的实际授权方式提供操作。可用时显示“可用”并直接连接；Portal 首次未授权时引导用户在被控机确认屏幕和输入访问；成功授权后显示“已授权”，隐藏授权提示并恢复普通连接按钮。当前设备仍禁止自连接，并提示从另一台设备连接。会话、桌面共享组件或所需能力不可用时显示具体原因、“查看原因”和“重新检查”，不显示无效的申请权限按钮。诊断会读取实际能力，不创建空的授权会话。Mac/Windows 的系统授权入口保持原行为，LightOS 实例继续使用来源提供的权限和连接地址。

Portal RemoteDesktop v2 支持时申请恢复令牌，只有系统在真实授权、有效首帧及会话身份复核后返回的令牌才会缓存。令牌按本机用户、桌面提供者和显示会话端点隔离，保存在当前用户私有状态目录中，目录权限 0700、文件权限 0600。原子更新和跨进程锁保证单次消费；失败或取消后不会重放已消费令牌。运行时重启和升级保留系统已批准的恢复信息，每次连接仍重新校验当前桌面身份并由系统验证恢复请求。权限诊断同时读取成功授权记录和存活会话，避免画面已可用却仍显示待确认。系统撤销、授权失效或不提供恢复令牌时仍可能需要确认；拒绝或取消不会自动重试，也不会回退到虚拟桌面。

`lzc-cli project build` 依次构建 Web 前端、四个平台的原生程序及其压缩清单、Go 管理服务，输出 `dist/` 中的完整 LPK。缺少任一平台会中止构建，不从 PC 仓库复用预编译程序。原生源码摘要和程序摘要一致时复用本地构建缓存；修改原生版本或源码后自动重新编译。将文件拖到目标微服桌面覆盖升级，再从设备卡片手动安装或更新远程桌面。

构建入口为 `scripts/build-runtime-artifacts.py`，本机配置写入忽略的 `.local/runtime-build.json`，格式见 `config/runtime-build.example.json`。默认 Linux 构建宿主为 x86_64 Linux，需要 Python 3.11+、Rust、Node、Go、bubblewrap、bsdtar、cargo-xwin 和 LLVM 工具链。Linux 在校验过摘要的 Ubuntu 22.04 根文件系统中编译，以保持支持的 glibc 基线；可通过 `linux.command` 指定返回实际程序路径 JSON 的构建命令。Windows 使用静态 CRT 交叉编译。macOS 需要可通过 SSH 连接的原生 Mac 构建节点、Xcode 命令行工具、Rust 两个 Apple 架构目标、CMake 和 NASM；SSH 凭据由本机 SSH 配置管理，不写入仓库。

macOS 正式发布应配置稳定的签名身份，始终保持应用标识和签名团队，避免升级后重新申请系统权限；未配置时使用临时签名，仅适合开发。硬件编码依赖由 `config/codec-dependencies.json` 固定下载地址和摘要；Windows/Linux 使用 LGPL 共享库，macOS 从固定源码构建 VideoToolbox 所需的最小共享库并随应用签名。客户端无需自行安装 FFmpeg。构建产物和本机签名身份保存在忽略目录，不提交二进制或设备登录凭据。

原生主机构建用 `cargo build --release --locked --features bundled-jpeg --bin lightos-remoted`，前端先执行 `npm run build`。Windows 使用静态 CRT，保证没有安装 VC++ 运行库的机器也能直接运行。使用 `RUSTFLAGS` 覆盖 Cargo 配置时，需同时保留 `.cargo/config.toml` 中的静态运行库选项。macOS 27 配合旧 Rust 编译器时，本机快速构建可设置 `CARGO_PROFILE_RELEASE_STRIP=none CARGO_PROFILE_RELEASE_BUILD_OVERRIDE_DEBUG=2`，避免工具链裁剪编译期宏库导致的 LINKEDIT 错误。

人工验证未安装及关闭时设备可见、匹配平台下载、安装进度、版本差异、取消或确认运行中的更新、已关闭时直接更新、切换后的旧版本清理，以及权限申请、启停、实际画面和封面保留。macOS 和 Windows 分别记录真实交互会话；桌面浏览器的移动视口只能验证布局，不能算物理手机验证。不新增自动真机场景，也不把编译、HTTP 成功或只出现 Canvas 当作完整画面与输入验收通过。
