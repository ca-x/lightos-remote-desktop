# v0.1.22: explicit offline Linux package staging

- Add `install-service --package-managed --stage-only` as a read-only Rust
  validation path for an already-installed Linux package. It checks the regular
  executable and the exact two binary-exported units without running embedded
  scripts, systemctl, NSS helpers, the doctor, or the desktop.
- Reject special files through an O_PATH-only check before any data open, then
  read the pinned regular inode through Linux procfs. FIFOs and device payloads
  never receive a data-open operation from the staging validator.
- Allow fresh rootfs/OCI preparation with
  `LIGHTOS_REMOTED_PACKAGE_STAGE_ONLY=1 pacman -U ...`. Main package hooks defer
  activation/snapshot/removal; the codec hook skips transport refresh. No account,
  authentication, recovery state or service enablement is created offline.
- Reject explicitly empty and other invalid staging values before any hook
  command. Unset/0 retains ordinary installation and upgrade behavior.
- Preserve existing service names, platform authentication paths and normal
  transport-only upgrade recovery. Activate on the configured booted instance
  using the existing `install-service --package-managed` command.

Staging is not Niri support or desktop activation. The default owned virtual
desktop remains Cage/Hyprland unless a supported target is explicitly selected.
It does not prove physical VT handoff, platform-proxy connectivity, actual
encoding, or Windows/macOS hardware acceptance. Existing authentication must
remain per-instance and platform-owned, never baked into an image.

新增 Linux 包离线预装模式：构建镜像时只验证已安装文件，不创建共享密码、账号或启动
服务。首次启动仍复用原有平台配置和原生激活流程；此次版本不冒充 Pond/Niri 桌面适配。
