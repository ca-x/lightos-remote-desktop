# v0.1.1

## Changes

- Replace stop-and-wait video credit with a bounded, render-ACK-timed window of
  one to three frames. First frames after codec/resolution changes still require
  acknowledgement before expansion; stale IDs cannot release current credit.
- Fix overlapping H.264 decode watchdogs that could incorrectly fall back to JPEG.
- Add toolbar switching between the default persistent virtual desktop and an
  existing same-user Wayland desktop, without restarting the service or closing
  virtual applications. A page reload returns to the default desktop.
- List and select active compositor outputs by name and resolution. Capture and
  pointer mapping use the same selected output; rotated output metadata is corrected.
- Physical mode rejects monitor resizing on both client and server. Discovery,
  unavailable states and connection failures are explicit. The existing draggable
  floating toolbar remains dependency-free and keyboard-accessible.

## Validation and limits

Local tests cover Rust, frontend, installer/compatibility, live clipboard/audio
protocol, multi-output attachment, per-output pointer mapping, rejected physical
resizing and return to the retained virtual session. Controlled 120 ms render-ACK
delay reproduced approximately 8 FPS before the fix and 18–20 FPS after it on the
original 1280x720 test workload, with roughly 30 FPS in the no-delay JPEG control.
This does not measure WAN input-to-display latency or guarantee all perceived
latency is resolved.

This machine has no physical login Wayland socket. Attachment and multi-monitor
tests use an isolated existing compositor, not physical display hardware. Wayland
discovery can list headless outputs; it is not a DRM connector inventory. The
physical compositor must support screencopy and virtual keyboard/pointer protocols;
per-output pointer mapping requires virtual-pointer v2. Physical audio is not
implemented. CPU H.264/JPEG, WebSocket transport and other v0.1.0 limitations remain.

## Upgrade

Extract the Linux x86_64 archive and run:

```sh
sudo ./lightos-remote-desktop install-service
```

The transactional installer retains authentication, the original Python payload,
and rollback support. `rollback-service` restores the previous transaction, which
may itself be a Rust version. Do not replace system Aquamarine libraries.
