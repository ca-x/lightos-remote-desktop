# v0.1.2 · 原生媒体与 Linux 热路径优化

## Changes

- Replace runtime FFmpeg subprocesses with an in-process, source-built OpenH264
  encoder and native PulseAudio capture. Retain WebCodecs, JPEG fallback,
  bounded render acknowledgements, cancellation and resize handling.
- Avoid redundant JPEG encoding in H.264 mode and share captured RGBA pixels
  with the encoder. Reuse Wayland capture connections in bounded batches and
  enable TCP_NODELAY without changing global system settings.
- Refresh output state after transient screenshot failures; explicitly missing
  selected monitors still report an error rather than silently changing capture.
- Show the software version in the floating toolbar, including before connection.

## Validation and limits

Rust, frontend, clippy and release-build checks pass locally. Isolated candidates
also cover real video/audio, resizing, output selection and worker teardown.
The local installation passes the transactional installer and authenticated
HTTP/version checks. Rollback restores the previous v0.1.1 installation.

Short local 1280×720 samples compared with the unoptimized native implementation
show process CPU falling from about 65% to 41% with a simulated 120 ms render ACK,
while throughput rose from about 19 to 22 FPS. Near-zero ACK throughput remains
about 29 FPS. These are local workload samples, not end-to-end WAN latency results.
OpenH264 traffic remains higher than the previous FFmpeg encoder in the sampled
workload; bitrate efficiency is not resolved by this release.

This is software encoding, not GPU zero-copy or hardware encoding. Multi-output
validation uses headless compositor outputs; physical hardware combinations are
not comprehensively tested. Physical-session audio remains unsupported.

## Runtime and distribution

The binary now requires system libpulse even when audio is disabled. OpenH264 is
built from source; upstream and wrapper license notices accompany the archive.
This does not claim coverage under Cisco's distributed-binary patent arrangement.
FFmpeg is optional for development decoding tests, not a runtime requirement.
