# v0.1.19: Windows and macOS host foundations

- Add experimental native physical-desktop hosts for Windows and macOS 13+, with
  foreground execution and one-command native service installation.
- Share desktop, display, audio, permission, lifecycle, service and private-storage
  contracts across platforms while retaining Linux virtual desktops and service
  names. Browser transport, codec preferences and scheduling remain shared.
- Use Windows Graphics Capture and WASAPI, macOS ScreenCaptureKit and system
  audio, and Enigo/arboard input and text clipboard adapters. Permission probes
  remain read-only. Lock and permission transitions withhold video/audio; failed
  input-release acknowledgement prevents another controller from taking over.
- Supervise the Windows host in the selected interactive user session; use a
  per-user macOS LaunchAgent with transactional updates and a stable app path.
- Build Windows x86_64, macOS ARM64 and macOS Intel packages on native CI runners,
  including a native ARM runner for macOS ARM64. Linux releases and both AUR bin
  packages continue through the existing tag-driven publication chain.

Windows/macOS support remains experimental pending interactive capture, input,
audio, lock/unlock and service acceptance on each system. CI build/unit coverage
does not establish that acceptance. Physical resolution changes, independent
virtual displays, secure/login desktops, and physical-desktop MCP/RDP control
are outside this version's scope. See [installation and capability limits](../cross-platform-host.md).
