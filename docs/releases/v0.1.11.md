# v0.1.11: 新工具栏、统一服务安装与 RDP 设置

## Changes

- Compact toolbar with display, keyboard, clipboard and connection menus; independent settings dialog for streaming, appearance, MCP and RDP. Menus follow all four docking edges, remain accessible on small screens and work inside fullscreen. Existing preferences and active connections survive opening settings.
- Unified executable and release archive names: `lightos-remoted` and `lightos-remoted-linux-x86_64.tar.gz`. The optional `lightos-codec-ffmpeg` keeps its existing name. Project code is now licensed under MIT; third-party notices remain included.
- AUR package `lightos-remoted-bin` installs the executable under `/usr/lib/lightos-remoted`, with `/usr/bin/lightos-remoted` as the command. Fresh installs initialize and start both services. Normal upgrades restart the transport while preserving the desktop owner and its applications.
- The executable now owns both complete service definitions and their shared lifecycle. Standalone `install-service` supports fresh installs; AUR exports the same units from the binary and invokes its lifecycle commands. Both Chinese and English READMEs are included, with mutual language links.
- Settings now includes RDP enable/disable and port controls. TLS identity is generated and persisted automatically unless explicitly configured. Listener changes keep HTTP and the desktop owner running; port/TLS/save failures preserve the previous listener. RDP quality remains client/protocol negotiated.
- Existing LightOS service names and authentication files are retained. Legacy manual installations remain running until the user follows the README migration steps; obsolete local service overrides must be removed during that migration.

## Validation

- The toolbar baseline passed 91 Node and 23 Vitest tests, 162 all-feature Rust tests, strict Clippy, formatting and release compilation. Subsequent service/RDP settings increments use focused checks: 7 installer CLI tests, 88 shared installer fixtures, 24 release guards, 31 package/lifecycle cases, 17 RDP tests and 16 settings component tests. The package fixture also passed 26 checks with the actual binary exporter. Legacy installer 43 and compatibility 13 checks remain covered.
- Real browser checks covered 32 menu placements after dragging to four edges and four corners, narrow and landscape viewports, focus trapping/return, dark/light themes and reduced motion.
- An isolated native desktop delivered H.264 frames to the redesigned interface, kept its connection across menu/settings interactions and displayed settings inside fullscreen. Served JavaScript/CSS matched the built assets. This integration harness used a local authentication proxy; a direct authenticated WebSocket handshake was checked separately.
- AUR packaging includes bootstrap/release guard fixtures and a real nonroot makepkg build of its private patched Aquamarine library. No package installation or production service migration was performed on the development host.

## Installation and migration

After AUR publication, install with `yay -S lightos-remoted-bin` and update with `yay -Syu`. See [AUR details](../aur.md) and the [old-install migration instructions](../../README.md#老用户迁移与清理旧版手动安装).

The private Aquamarine compatibility library targets Aquamarine 0.15.1 / SONAME 14 and must be revalidated when Arch changes that ABI. Fresh dedicated-user systemd activation was covered with fixtures rather than a fresh-machine deployment. Optional hardware encoding and MCP retain their documented setup requirements and limits. RDP retains its protocol limits and loopback default; the new settings entry provisions TLS automatically. No additional full build or FreeRDP run was required for these focused increments; final tag CI builds the release assets.
