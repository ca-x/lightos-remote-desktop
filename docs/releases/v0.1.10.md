# v0.1.10: 硬件编码、MCP 桌面操作和 RDP 接入

## Changes

- Optional native H.264 worker for VA-API, NVENC, AMF and VideoToolbox, with bounded encode/decode probes, saved automatic/manual backend selection, and software fallback when a backend fails. The portable core keeps its built-in encoders and does not link FFmpeg.
- Disabled-by-default MCP desktop access: manage observe/control tokens in the tools panel, then use screenshot, pointer and keyboard tools over authenticated Streamable HTTP. Token revocation, request cancellation and deadlines reach queued native input. Browser, MCP and RDP share exclusive desktop control.
- Optional TLS RDP access to the same owned virtual desktop. Release binaries include the feature, disabled at runtime until a certificate/key are configured. RDP forwards bitmap updates and validated input without starting another desktop or restarting the desktop owner.

## Validation

- Default and bundled-JPEG workspace suites: 144 passed each. All-feature suite: 159 passed, with environment-specific tests run separately. Strict all-feature Clippy, formatting and frontend build passed; 88 Node and 19 Vitest tests passed.
- All 43 installer and 13 compatibility fixtures passed. An integrated HTTP/WebSocket/MCP/RDP test verified exclusive control and release after cancellation.
- Native Omarchy Lua initialization, two transport generations with the same Ghostty/compositor, and native Unicode cancellation/keymap recovery passed in isolated desktops.
- FreeRDP over TCP/TLS verified bitmap channels, input, resolution changes, reconnection, certificate validation and rejection of wrong/empty credentials and plaintext downgrade.

## Runtime

The optional FFmpeg worker requires matching system FFmpeg ABI and GPU drivers. The Ubuntu 24.04 worker archive is separate; build it locally for Arch/Omarchy. Build tools such as Clang are not runtime requirements for the core. No positive hardware encoding or performance result is claimed for this host.

Capture/input remain Linux Wayland. Other desktop adapters retain their documented validation limits. RDP uses TLS password authentication, without NLA/CredSSP, audio, clipboard or client-requested desktop resizing. MCP offers standard desktop tools; direct compatibility with Cua's separate driver protocol is not claimed. MCP and RDP are off by default. See the hardware, MCP and RDP documentation for setup and limits.
