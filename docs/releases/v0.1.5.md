# v0.1.5 · 音频低延迟与播放优化

## Changes

- Reduce audio traffic with 128 kbit/s stereo Opus on compatible browsers. Local measurements show about 132 kbit/s including application headers, compared with 3.07 Mbit/s for the previous PCM stream, without lowering video resolution or encoder quality.
- Give audio its own authenticated connection, decode it in a browser Worker and play through an AudioWorklet with bounded buffering. Muting or an audio failure no longer disconnects the desktop; older browsers and clients retain PCM compatibility.
- Add encode, socket-send, render-ACK and browser decode/draw P95 diagnostics to the FPS/RTT tooltip, together with audio codec, buffer duration and underrun counters.
- Include the fullscreen resolution fix from the unpublished v0.1.4 candidate: switching from a manually reduced resolution no longer stretches a stale low-resolution image.

## Validation and limits

Local checks pass: 65 Node tests, 3 React tests, 54 Rust library tests, normal
integration tests, clippy, release build and installer checks. Explicit live tests
cover Opus decoding of a nonzero signal, PCM compatibility, authentication and
Origin checks, audio continuing while video ACKs are withheld, and session cleanup.
A local animated desktop stays near 30 FPS with audio off and Opus on; this is not
a guarantee of the same frame rate or latency over every remote connection.

Refresh the browser after upgrading to load the new audio pipeline. Opus requires
browser Worker WebCodecs audio support; AudioWorklet requires HTTPS or localhost.
PCM fallback still uses more bandwidth. Physical-session audio remains unsupported.

## Runtime and distribution

The executable embeds all frontend assets, including the audio Worker and
AudioWorklet modules. libopus is built from locked source and statically linked
for the application codec; Node.js and FFmpeg are not runtime requirements.
GitHub Actions builds the frontend before Rust and packages the codec notices
alongside the Linux x86_64 archive and SHA256 checksum. Existing native desktop
and Pulse/PipeWire dependencies still apply.
