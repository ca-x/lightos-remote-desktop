# 可集成运行时与独立 LPK

本仓库同时提供跨平台远程桌面运行时与独立 LPK。运行时的采集、输入、认证、
浏览器协议与平台适配保留在本仓库；集成方只需要运行时二进制和生命周期适配。
LPK 的管理页与管理服务由 `manager/` 维护，根目录 `lzc-build.yml` 负责打包。
两者不依赖 LightOS 管理应用或桌面客户端的内部 Go 包与源码。

## 构建独立 LPK

在本仓库根目录执行：

```sh
lzc-cli project build
```

输出到 `dist/`，显示名称为“远程桌面”。管理服务内嵌自己的页面和专用图标，
不从其他管理应用或桌面客户端复制源码。桌面来源接口返回已授权连接 URL，
当前用户通过平台委托访问这些既有接口。物理机直接向本应用登记，不依赖
LightOS 增加接口、保存远程桌面字段或升级。页面只展示可连接选项，
详细接入方式见[独立应用说明](management-lpk.md)。

## 运行时交付

[`integrations/client-runtime/releases.json`](../integrations/client-runtime/releases.json)
记录当前集成使用的发布版本、源码提交、四个平台的原始压缩包和程序摘要。
Windows x64、Linux x64、macOS x64/arm64 的程序与浏览器资源一同发布；macOS
保留 `.app` 的可执行程序与 Info.plist，作为稳定的系统权限授权身份。

集成方只携带对应平台二进制、必要的 bundle 文件和摘要清单。
不携带本项目的开发文档、研究记录、测试证书或完整发布压缩包。升级时同时更新
二进制与摘要。若安装包签名改变了可执行程序，签名后刷新安装包中的
程序摘要；原始发布包摘要继续用于追溯来源。

Linux 发布包依赖系统的 PipeWire、PulseAudio、Wayland 与 xkbcommon 等运行库，
不是静态链接程序。macOS 至少为 13，用户需为随包程序授予屏幕录制与辅助功能权限。
Windows/macOS 沿用上游实验性状态，需在各平台单独进行真实交互验收。

## 生命周期接入

集成方以当前登录用户运行 `lightos-remoted serve`，通过环境变量传入随机的回环
端口与每次启动重新生成的认证密码，不在命令行中携带密码。Linux 显式传入当前
Wayland socket 或 X11 display，避免创建虚拟会话。运行时的 `/healthz` 提供当前
进程标识、就绪与本机授权状态，集成方核对后才公布连接入口。

桌面客户端的开关默认开启。其生命周期适配管理独立登录启动项，关闭时停止程序
并移除该启动项，保持用户普通客户端自启动偏好独立。物理机连接绑定已验证的
账号、微服、设备与远程桌面启用代次，通过平台设备 HTTP 服务访问回环端口；切换身份、
关闭远程桌面或退出客户端时停止运行时。认证续期中断后在 35 秒租约到期时停止。
“接入 LightOS”只控制终端授权，远程桌面不会调用 LightOS 实例接口或启动 PTY。
这些是集成策略，远程桌面程序本身仍可由其他集成方或独立服务启动。

Wayland Portal 等待本机授权时，管理页允许进入对应运行时完成系统授权流程，
不把等待授权的状态伪装成已完成画面采集。macOS 权限、Windows 当前登录桌面和
Linux 各显示协议需分别手动验收，构建结果不代表这些场景通过。
