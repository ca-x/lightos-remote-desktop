# 观看端键盘接管

键盘焦点、输入法策略和释放逻辑由远程桌面网页维护，PC 客户端没有新增 IPC、快捷键或原生钩子。PC 仅负责原有设备登记、运行时更新与生命周期。

鼠标在画面内且窗口聚焦时，PC 网页转发物理键码，让目标机器处理输入法和快捷键；手机软键盘继续发送确认文本。鼠标移出、窗口失焦、打开工具面板、断开连接及 Ctrl+Alt+Shift+Esc 都释放远端按键和鼠标按钮。显式粘贴本地内容仍可用，物理 Ctrl/Command+V 使用远端按键语义。

普通浏览器不能承诺拦截窗口模式下的所有操作系统快捷键。全屏时使用浏览器 Keyboard Lock；没有系统接管能力时页面显示限制，不能把浏览器捕获视为全系统捕获。

LPK 入口可复用**观看设备自身**已开启的远程桌面运行时提供原生接管。管理服务按网关认证的当前设备 ID、账号归属和运行状态选择观看设备，通过既有受认证的设备服务代理访问 `/viewer-input`。目标可以是容器或物理机；被控设备不负责抓取观看端按键。直接连接容器且未经过管理入口、观看设备未登记或运行时关闭时，使用浏览器路径。

原生能力由同包的 `lightos-input-capture` 提供：Windows 使用低级键盘钩子，macOS 使用需要系统授权的 Event Tap，Linux 使用 X11 grab 或支持 layer-shell、foreign-toplevel 和 shortcuts-inhibit 的 Wayland 合成器。Linux 需要运行于观看设备的实际图形会话；隔离容器内的运行时不能接管宿主输入。未支持协议的 Wayland 桌面保留浏览器路径。系统安全按键仍受操作系统限制。

接管采用短租约：单实例、窗口标题及焦点校验、页面心跳、父进程退出回收，1.5 秒无心跳即停止。macOS/Windows 同时检查鼠标是否仍位于原窗口；页面负责画布边界和工具面板。页面释放会关闭 WebSocket 并结束辅助进程。工具启动失败不能显示为接管成功。验证必须覆盖真实物理按键、输入法、窗口切换和鼠标移出；模拟 DOM 事件不能证明系统快捷键已被拦截。
