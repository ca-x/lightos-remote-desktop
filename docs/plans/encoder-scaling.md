# 编码前缩放实施计划

基线：main `629a6c7`。按用户授权在 main 实现，保留现有高 DPI、独立光标、JPEG 4:4:4 与物理桌面保护。

1. 在 media-codec 接入 FIR bilinear、复用 Arc 输出缓冲及同尺寸透传，验证尺寸、缓冲所有权和真实编码/解码。
2. WebSocket 协商可见像素上限，区分捕获/编码尺寸；接入编码及静态刷新，保持 ACK、H.264 配置和隐私 epoch 语义。
3. 浏览器按 CSS × DPR 提交适应窗口上限，清晰优先/原始大小请求原生；桌面相关 UI 和坐标继续使用捕获尺寸。
4. 跑针对性 Rust、前端及协议回归，检查实际接入耗时，更新双语文档，审查后提交推送。无需重跑完整研究矩阵，用户追加授权发布 v0.1.16，沿用 tag 自动发布，不修改本机服务。

重点审查：异步解码中尺寸归属；锁屏时残留像素；静态桌面切换尺寸；旧端兼容；物理显示器与虚拟桌面自动分辨率不被编码尺寸干扰。

集成更新：合入上游 `66b6fa8` 的物理桌面局部缩放，放大时恢复原生编码，保持编码尺寸变化前后的平移与缩放状态，并补充回归。
