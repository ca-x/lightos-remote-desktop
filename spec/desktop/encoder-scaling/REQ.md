# 编码前缩放

适应窗口时，支持该能力的浏览器按可见区域的 CSS 尺寸 × DPR 请求编码尺寸上限。服务器保持宽高比，只缩小，不放大；编码尺寸不能改变桌面、显示器模式、输入归一化坐标或独立光标的坐标单位。原始大小、清晰优先及物理桌面局部放大使用原生尺寸。编码尺寸变化保留局部缩放与平移，只有源桌面尺寸变化才重置局部缩放。未协商能力的客户端继续使用原生尺寸。

使用 `fast_image_resize` 的 SIMD bilinear 路径，只在确实需要降低编码分辨率时执行，并复用输出和内部缓冲。原生路径保持 capture Arc 透传和 JPEG 缓存。缩放在 blocking worker 执行，不阻塞异步运行时。JPEG 保留 4:4:4。

每帧关联捕获尺寸，浏览器分别维护捕获和编码尺寸；桌面分辨率菜单、自动分辨率去重和原始大小布局使用捕获尺寸。编码尺寸变化重建 H.264 编码器及配置，重置 ACK 窗口，即使画面静止也刷新。隐私状态变化清理缩放缓存并保留现有 epoch 检查。

编码耗时和网络拥塞继续由现有调度器处理。本功能不根据像素数推断带宽收益，也不根据短期网络波动反复修改尺寸。缩放后文字可能损失细节，清晰优先提供原生保真选择。
