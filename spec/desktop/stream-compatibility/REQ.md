# 桌面客户端与编码组件兼容

## 背景

用户在桌面客户端使用自动编码打开物理桌面时，报告首帧出现后黑屏，光标显示为方块。通过管理页代理入口检查发现，物理桌面的后续原始图像就含有黑区，而同一显示器的完整截图正常；移动鼠标后会触发问题，且物理会话实际加载了临时路径中的旧光标适配组件。主服务升级后使用已安装的旧编码组件时，硬件编码也会因帧传输能力不匹配而失败。

## 需求目标

物理桌面的采集缓存复用时，每一帧都保持完整有效的桌面内容，局部重绘不能覆盖未变化的区域，光标绘制不能破坏后续画面；首帧、编码协商和后续画面保持连续可见，光标保留远端真实形状、透明度和热点。桌面客户端使用与自身绘制环境兼容的解码和独立光标显示路径；兼容处理不把光标合入视频，也不绕过桌面锁定保护。

主服务与可选编码组件独立升级时，只有双方确认支持的帧传输能力才会启用。旧编码组件继续接收完整有效的帧，不能因为未支持新的传输方式而收到空帧或无效帧；支持新能力的组合继续使用其优化路径。

## 范围

桌面客户端的浏览器画面解码、独立光标展示，以及主服务与可选原生编码组件之间的兼容协商。

## 非目标

更改用户物理显示器、解锁桌面、重启持久桌面会话、修改客户端安装或取消已有权限检查。客户端实机显示结果由开发者复核。
