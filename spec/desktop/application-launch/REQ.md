# 应用启动的桌面归属

## 背景

虚拟桌面与物理桌面可属于同一 Linux 用户。浏览器和网页应用除了显示连接，还会根据用户数据目录复用已有进程；共用目录会把虚拟桌面的启动请求转交给物理桌面的浏览器，当前桌面因此没有窗口。

## 需求目标

从虚拟桌面的应用菜单、浏览器入口、网页应用快捷键和打开链接入口启动应用时，窗口属于该虚拟桌面；物理桌面启动应用时继续属于物理桌面。已存在的另一桌面浏览器不能接管正常启动请求。
保留独立的显示连接与私有 D-Bus，虚拟桌面的 Chromium 系浏览器使用按桌面区分且可跨重启保留的数据目录。两侧浏览器登录状态和浏览数据独立；不复制或改写物理桌面的现有配置。
虚拟会话中的 Chromium 启动默认使用已验证的 Wayland 连接，不依赖宿主强制 X11 的配置。GTK 桌面入口通过私有副本适配，不修改系统桌面入口；其他应用保持原有启动方式。外部物理会话不安装或注入启动桥接。
同一虚拟桌面多次打开网页应用可以复用本桌面的浏览器进程；不同虚拟桌面之间同样不共享浏览器单实例。安装更新时刷新已运行桌面的本地启动桥接，不终止桌面或现有应用。
启动桥接只在所属会话中工作。会话不匹配或显示端点不存在时明确失败，不回退到其他桌面。

## 范围

本工具拥有的虚拟会话、Omarchy 应用启动链路、Chromium 系浏览器与网页应用，以及私有 D-Bus 的应用激活环境。

## 非目标

改变物理桌面配置；迁移已打开的窗口；复制网站登录凭据；为任意第三方应用提供操作系统级安全沙箱；覆盖用户在命令行中显式指定的浏览器数据目录或显示后端；自动修改物理桌面的浏览器配置。
