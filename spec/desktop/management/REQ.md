# 远程桌面管理

## 背景

用户需要从独立应用查看和打开当前账号可用的容器和物理机桌面。已能打开的桌面不应因管理页要求升级其他应用而消失。

## 需求目标

独立 LPK 的名称为“懒猫远程”，保留原包 ID 以便覆盖升级。用户以带封面的设备卡片查看容器和物理机，看到设备名称、系统、远程桌面运行状态和已安装版本；页面只展示在线设备，不增加搜索或其他管理应用入口，也不提供手动刷新按钮；可见时自动更新状态，返回页面后立即更新。标题和主题操作所在的顶部栏吸顶固定，列表滚动时保持可见并尊重顶部安全区。整个管理界面与应用图标采用黑白灰简约风格，支持明暗主题，并沿用微服管理页面的沉浸式导航约定与宿主安全区，内容和操作不能被状态栏或关闭按钮遮挡。

首次使用时不要求安装远程桌面二进制。客户端主进程内置轻量控制模块，复用已登录的懒猫网络并持续登记当前账号拥有的设备；从其他设备访问时，无论是否安装远程桌面都显示设备卡片。桌面采集服务默认关闭，关闭桌面不退出控制模块，设备仍能从管理页安装或再次开启。PC 设置页不再提供远程桌面开关或权限入口。启停状态按账号和设备保存，重启控制程序后继续尊重用户明确选择；切换账号不得沿用其他账号的启用决定或旧控制授权。

设备名旁的开关决定是否允许连接该物理机，首次安装默认开启，用户手动关闭的设备在重启和升级后保持关闭。开启后卡片左上角显示“运行中”，等待连接期间桌面服务可以停止。进入桌面窗口时启动服务，关闭总开关时立即禁止新连接（包括已保存的桌面地址）、断开现有连接并停止服务。权限状态独立显示。总开关开启且没有桌面连接时，未授权设备仍提示所缺权限，用户可在卡片上发起系统授权。申请、批准或取消均保留总开关的选择。待授权或启动失败时在卡片中显示原因。离线设备从列表隐藏，重新上线后恢复已有开关选择和预览。

物理机和 LightOS 实例使用统一的紧凑卡片，正文固定为设备名、系统和版本三行，采用紧凑的相等行距，同行文字与操作入口居中对齐。已安装的物理机在设备名右侧仅显示菜单图标，展开后按是否允许连接显示“开启远程桌面”或“关闭远程桌面”，其下依次为防止休眠和“卸载远程桌面”；物理机系统名后显示“权限已批准”或“权限未批准”；Windows 需要锁屏访问授权且仅缺少该授权时显示“仅在桌面解锁时可访问”，并保留“请求设备权限”入口。Windows 确认当前桌面账户使用空密码且桌面可直接访问时，按屏幕和输入权限显示状态，隐藏锁屏授权提示及对应申请入口。如果该账户实际停在系统锁屏界面且无法连接，提示在本机解锁。只有屏幕和输入权限均获批准才显示已批准，未知状态不冒充批准。未批准文案右侧显示“请求设备权限”，使用与更新入口相同的蓝色文字样式，设备未安装运行时或不支持控制时入口不可操作；不常驻展示屏幕录制和键鼠权限清单。更新入口位于当前版本右侧，以蓝色可点击文字显示；未安装时在同一位置显示安装入口。卡片底部不保留独立操作区。设备名左侧显示所属平台标志：macOS 使用 Apple、Windows 使用 Windows 标志，Linux 根据已知发行版区分 Omarchy、Debian、Arch 和 Ubuntu，无法识别的发行版使用通用 Linux 标志；不按设备名称猜测系统。图标保留平台品牌原色，不统一套用黑白着色；仅 Apple 使用适配明暗背景的黑白版本。实例类型显示“LightOS实例”。标题下方的说明为“懒猫微服网络保障您的隐私和数据安全。”。

macOS、Windows 和使用 systemd 的 Linux 物理机可单独设置持久防休眠。首次安装沿用系统电源设置。设备允许休眠时显示“申请禁用休眠”，已经防止休眠时显示“关闭防止休眠”，包括用户已在系统中自行开启的情况。申请成功后接电、电池和笔记本合盖时均保持运行，重启后继续生效。关闭时优先恢复原方案，没有备份时恢复系统常规休眠配置。需要管理员权限时在被控机确认，拒绝、超时或无法读取系统状态时不显示操作成功。状态仅在管理页可见并展开对应菜单时读取，管理其他设备、切换到后台或关闭页面时停止查询。防休眠独立于远程桌面总开关和连接状态。

整块预览是桌面连接入口，预览底部居中以纯文字显示“点击进入桌面”，文字靠近下沿，底部深色渐变向上淡出，不使用胶囊、边框或毛玻璃，点击后进入对应设备已授权的桌面。总开关已开启且具备连接权限的物理机在服务空闲时也显示进入提示，点击后自动启动，窗口等待桌面就绪再连接。最后一个桌面连接断开后自动关闭服务，给刷新窗口和短暂重连留出 5 秒。未安装、等待授权和当前设备继续提供对应的状态和操作。预览左上角显示运行状态，状态采用小尺寸圆角胶囊、低不透明度的状态色底和同色文字，预览画面能清楚透过底色，不设边框并靠近预览左上角，并带左侧状态圆点；物理机总开关开启为绿色“运行中”，关闭为灰色“已关闭”，明暗主题使用相同结构，不使用背景模糊或毛玻璃；错误说明在状态下方以当前主题的纯色背景文本块展示，长内容在块内滚动。安装更新进度也显示在预览覆盖层。错误、权限、版本及进度变化不改变卡片正文与预览尺寸，相同宽度的卡片高度保持一致。

卡片封面仅保存用户成功连接后实际看到的有效画面，物理机与 LightOS 实例均适用，没有连接画面时显示“暂无预览”；关闭桌面或重启管理服务不会清除上次连接封面。预览与设备控制都限制在当前设备所属账号。

管理服务继续消费既有容器桌面来源返回的连接 URL，不要求升级容器管理应用。可选来源不可用时保留其他设备并明确提示；未登录不能伪装成零设备。远程桌面不依赖“接入 LightOS”、终端或 PTY，启停不改变终端授权。连接与控制操作都重新核对当前账号、设备归属与在线状态。

LPK 构建入口自动从当前源码构建并收录 Mac ARM64、Mac Intel、Windows x64 和 Linux x64 的压缩运行时、同版本硬件编码辅助程序、必要的 FFmpeg 动态库与版本、大小、校验清单；不复制 PC 仓库中预置的产物。macOS 由配置的原生构建机编译并使用稳定签名身份签名。客户端只通过当前微服应用的 HTTPS 域名下载匹配系统和架构的包，不访问第三方下载站。

设备卡片以“懒猫远程”标识运行时，物理机显示当前版本及存在更新时的最新版本。LightOS 实例来源提供版本时显示“懒猫远程 v版本 · 由 LightOS 管理”，无法取得版本时显示“版本和状态由lightos管理”，不以管理应用版本冒充设备运行时版本。未安装时显示“安装远程桌面”，版本或运行时摘要不一致时显示“更新远程桌面”，安装和更新使用版本行右侧的文字入口，进度与失败说明不会撑高卡片。在线物理机因旧 PC 客户端不具备安装更新能力时，保留禁用的安装或更新入口，并在卡片内明确提示先更新并重启被控设备上的懒猫 PC 客户端；提示不依赖鼠标悬停，支持中英文。具备安装更新能力时不展示客户端升级提示，离线或正在处理操作不误报为需要升级客户端，能力恢复后自动移除提示。两项操作都由用户点击发起，展示关闭服务、下载、校验、安装、检查及旧版本清理进度；成功完成后立即隐藏进度和完成提示。首次安装后允许连接，桌面进程按需启动，系统权限由用户主动申请。用户卸载后，设备的托管桌面程序及其版本目录被清理，版本行显示“安装远程桌面”，刷新列表与重启管理服务后均可重装。保留 Windows 单独批准的锁屏授权组件供重装后使用。

桌面服务实际启用时点击更新，先弹窗说明更新会中断当前连接，提供取消和确认。取消不改变服务和现有连接；确认后自动关闭服务，再下载安装，成功后恢复原有开启状态。已经关闭时直接更新且完成后保持关闭。更新期间禁止新连接与启停操作，不再等待用户手动断开。新版本未通过校验或运行检查时保留旧版本并恢复原有可用状态；成功切换后删除旧版本二进制。客户端自身不提供安装更新图形控件，仅负责状态、下载更新与生命周期。首次需要升级客户端以获得此控制能力，后续远程桌面程序更新只需升级 LPK。

当前客户端所在的在线物理机保留在设备列表及在线数量中；预览连接入口禁用并显示“当前设备”，其安装、更新、权限和启停操作继续按实际状态提供。通过微服平台提供的当前会话设备身份，与设备登记的稳定身份比对；不按名称、IP 或操作系统猜测。已安装、未安装、开启和关闭状态均遵循同一规则，管理服务重启后继续识别已登记的本机身份。身份无法确认时不误标其他设备。已有的本机连接链接也不得建立桌面连接，应提示改用另一台设备访问，避免循环采集。其他物理机和 LightOS 实例保持原有展示与访问规则。

Windows x64 与 macOS 的 Intel 和 Apple 芯片运行包均提供可选的 RDP 服务。首次运行时关闭 RDP，设备卡片继续使用浏览器桌面。用户可在已登录并获得屏幕和输入授权的被控机上，单独启动 RDP 服务并自行配置连接。

## 范围

未授权设备必须提供明确的独立权限申请入口。申请在管理页内展示进度和结果，不与进入桌面的操作混淆。成功保存授权后，权限检查结果更新为已授权，卡片隐藏申请入口；普通诊断刷新不能隐式申请权限。直接连接时如需设备端确认，应显示可见的等待说明。

通过 PC 客户端接入的 Linux、Windows 和 macOS 均属于物理机，默认连接其当前真实桌面，不能因权限、锁屏或接口不可用而静默回退到虚拟桌面。具备独立会话能力的设备允许用户明确选择“使用虚拟桌面”，独立桌面不包含物理桌面已打开的窗口，不解锁物理桌面，也不在物理桌面解锁后自动切回；桌面选择与保留行为由 [桌面切换](../switching/REQ.md) 定义。独立虚拟能力与物理授权分别展示；缺少组件或尚未支持的平台明确说明不可用，不以虚拟显示器或空白画面冒充独立桌面。Linux 按图形会话的实际能力选择原生 Wayland、X11 或 Portal。管理页区分可连接、待授权、会话不可用及接口不可用；尚不支持独立申请的旧运行时提示先更新，不展示无效操作。待授权设备引导用户申请权限并在被控机确认；其他不可用状态显示原因、处理建议和刷新状态入口。成功授权后权限检查结果应显示已授权，卡片移除申请入口和确认提示。系统允许时持久保存用户批准的远程会话授权，在断线、运行时重启和升级后自动恢复；系统撤销、拒绝或恢复失效时不得继续沿用。现有容器实例的桌面来源、连接和授权流程保持独立。

独立管理 LPK、设备卡片与连接预览、物理机登记及启停、系统权限入口、客户端控制模块、安装更新和 PC 集成。

## 非目标

不修改容器管理应用的代码，不自动安装容器桌面，不新增自动真机场景。画面、输入和平台系统权限由开发者手工验收。
